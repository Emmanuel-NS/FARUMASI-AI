# FARUMASI Pharmacist Assistant

Domain-specific question answering for community pharmacy in Rwanda: an assistant that answers
questions about medicines (uses, dosage, side effects, interactions, storage) and gives
first-line advice for minor health problems (headache, small wounds, diarrhoea...), while
recognising questions outside its scope and flagging risky situations.

> Student research prototype. It is **not** a substitute for a pharmacist or doctor.

## Problem

Patients in Rwanda often rely on community pharmacies as their first point of care, but
pharmacists are busy and trusted, plain-language medicine information is hard to find online.
FARUMASI (an online pharmacy platform in Rwanda) needs an assistant that can answer routine
medicine questions instantly, from trusted sources, and send people to a professional when it
matters. A general chatbot is unsuitable: it can invent doses and does not know when to stop.

Project type: **Domain-specific Question Answering (English)**, domain: medicines and minor
ailments, scoped to the WHO Model List of Essential Medicines.

## System overview

```
question ─► risk detector (rules) ─────────────────────────────► safety warnings
         └► greeting? (rules) ──► short introduction
         └► intent classifier (DistilBERT) ─► out of scope? ──► polite refusal
                                            └► retriever (fine-tuned MiniLM) ─► top-3 passages
                                                  └► reader (Qwen2.5-1.5B-Instruct + LoRA;
                                                             Flan-T5-base + LoRA fallback) ─► answer
answer + warnings + sources + disclaimer ─► Gradio web app
```

| Component | Baseline | Proposed (trained by us) |
|---|---|---|
| Intent / scope classifier (3 classes) | TF-IDF + logistic regression | DistilBERT fine-tuned, + real patient-question augmentation |
| Retriever | BM25 | all-MiniLM-L6-v2 fine-tuned with in-batch negatives; hybrid BM25 + dense (RRF) |
| Answer generation | Extractive (first sentences of top passage); Flan-T5 zero-shot; Qwen2.5-1.5B-Instruct zero-shot | Flan-T5-base + LoRA reader trained with hard negatives; Qwen2.5-1.5B-Instruct + LoRA chat reader (pharmacist-style answers, overviews, abstaining) |
| Risk detector | | Transparent rules (emergency, special populations, prescription-only) |

Design decision: the assistant **answers** risky questions but always adds a warning; for
emergencies (overdose, chest pain, breathing difficulty...) it leads with "seek urgent care, call
912 (SAMU)". Safety logic is rule-based on purpose so it is predictable and auditable.

## Data

All training and evaluation text is real, human-written data. Nothing was generated by an LLM
except the small challenge set described below.

| Dataset | Use | Size used | Licence |
|---|---|---|---|
| openFDA drug labels (US FDA) | Medicine passages (uses, dosage, warnings, side effects, ...) for 140 WHO essential medicines | 2,049 passages | Public domain |
| MedQuAD (Ben Abacha & Demner-Fushman, 2019) | Condition QA pairs (NIH, MedlinePlus, CDC...); questions from drug subsets for intent | 5,580 QA pairs | CC BY 4.0 |
| MedicationQA (Ben Abacha et al., 2019) | Real consumer medicine questions with trusted answers | 655 QA pairs | CC BY 4.0 |
| Rwanda FDA Patient Information Leaflets | Patient leaflets for Rwanda-registered products (local brand names, e.g. Coartem, Coversyl, Agycin): uses, precautions, dosing, side effects, storage | 187 leaflets → 590 passages, 760 QA pairs | Public regulatory documents, cited per leaflet URL |
| CLINC150 (Larson et al., 2019) | Out-of-domain queries for the intent classifier | 23,700 queries | CC BY 3.0 |
| ChatDoctor-HealthCareMagic (Li et al., 2023) | Real patient questions to augment intent training (weak labels, train only) | 3,416 questions | Apache 2.0 |
| Challenge set (`data/challenge/`) | 56 informal consumer-style questions, hand-labelled intent and risk, evaluation only | 56 | This project |

Preparation (`pharmqa/data/`): label sections are cleaned and split into ≤160-word passages;
openFDA questions use fixed templates over the real label text (documented limitation); splits
are **grouped by medicine/condition** so no entity appears in more than one split
(train 7,200 / val 1,136 / test 1,182 QA pairs in the Colab run). See `data/processed/dataset_stats.json`.

Rwanda FDA leaflets (`pharmqa/data/rwanda_pil.py`): text was extracted from the official PDFs and
committed as `data/external/rwanda_fda_pil.jsonl.gz` (the FDA site blocks scripted downloads).
Of 416 cached PDFs, 213 are scanned images with no text layer and were excluded (OCR was
slow and garbled words). Leaflets are split on their standard headings (patient-leaflet and
prescriber-style), questions are templated around the local brand name, and active-ingredient
groups get a larger held-out share (60/10/30) so the Rwanda test set (180 questions) is big
enough for the **before/after experiment**: retriever and reader trained with vs without the
Rwanda leaflet questions (`--exclude_source RwandaFDA-PIL`).

## Results

Full tables: [`results/summary.md`](results/summary.md) (generated by `python -m pharmqa.report_tables`).

**Intent classifier.** Models trained only on MedQuAD/CLINC score over 99% on the test split
but 39–55% on the realistic challenge set: they learned *writing style* (formal NIH phrasing vs
casual first-person queries) rather than topic. Adding real patient questions fixes most of
this; DistilBERT with patient questions is the best model on real consumer text.

| Model | Test acc | MedicationQA acc | Challenge acc | Challenge macro-F1 |
|---|---|---|---|---|
| TF-IDF + LR (word) | 0.993 | 0.528 | 0.393 | 0.372 |
| TF-IDF + LR (word + char) | 0.995 | 0.694 | 0.464 | 0.420 |
| TF-IDF + LR (word + char) + patient questions | 0.979 | 0.556 | 0.768 | 0.764 |
| DistilBERT | 0.998 | 0.917 | 0.554 | 0.486 |
| **DistilBERT + patient questions** (deployed) | 0.994 | 0.889 | **0.804** | **0.782** |

**Retrieval (1,182 test questions, 8,840 passages).**

| Model | Recall@1 | Recall@5 | MRR@10 | Topic@1 | Rwanda PIL R@1 | Rwanda PIL R@5 |
|---|---|---|---|---|---|---|
| BM25 | 0.322 | 0.706 | 0.478 | 0.852 | 0.444 | 0.917 |
| MiniLM zero-shot | 0.436 | 0.804 | 0.589 | 0.882 | 0.400 | 0.783 |
| MiniLM fine-tuned without Rwanda leaflets | 0.694 | 0.954 | 0.809 | 0.977 | 0.667 | 0.994 |
| **MiniLM fine-tuned (all data)** (deployed) | **0.695** | **0.958** | **0.810** | **0.977** | **0.678** | **0.994** |
| Hybrid BM25 + fine-tuned (RRF) | 0.551 | 0.867 | 0.684 | 0.951 | 0.689 | 0.967 |

- BM25 finds the right medicine/condition 85% of the time but the right *section* only 32%:
  most errors are aspect errors (e.g. returning "side effects" for a dosage question).
  Fine-tuning fixes most of these (topic@1 0.98, recall@1 0.70).
- On Rwanda leaflets, BM25 beats zero-shot MiniLM because local brand names (Coversyl,
  Biotrim) are rare exact-match tokens the pretrained encoder has never seen.
- **Rwanda before/after:** fine-tuning on the US/NIH data alone already lifts Rwanda recall@1
  from 0.40 to 0.67; adding the Rwanda leaflet questions adds only +1.1 points (within noise
  for 180 questions). The model mainly learns the question→section mapping, which transfers
  across sources; brand-name knowledge matters less once the section is right.
- Hybrid RRF is *worse* than the fine-tuned model alone: once the dense model is strong,
  fusing in BM25's weaker ranking pulls good passages down.

**Answer generation (400 test questions, stratified by source).** "Gold" context = the gold
passage shuffled with 2 BM25 hard negatives (tests the reader alone). "Retrieved" = top-3 BM25
passages in this run (the gold passage was in context for 59% of questions; with the fine-tuned
retriever it is 90%, see the earlier run in the git history).

| Reader | Context | ROUGE-L | BERTScore-F1 | Avg words | Rwanda PIL ROUGE-L |
|---|---|---|---|---|---|
| Extractive (copy top passage) | gold | 0.931* | 0.985* | 62 | 0.769* |
| Flan-T5-base zero-shot | gold | 0.191 | 0.761 | 9 | 0.147 |
| **Flan-T5-base + LoRA** (deployed) | gold | **0.608** | **0.900** | 37 | **0.479** |
| Extractive | retrieved | 0.395 | 0.833 | 60 | 0.460 |
| Flan-T5-base zero-shot | retrieved | 0.160 | 0.748 | 9 | 0.138 |
| **Flan-T5-base + LoRA** | retrieved | **0.414** | **0.841** | 35 | 0.429 |

\* Upper bound, not a fair comparison: references are the first sentences of the gold passage,
so copying the gold passage reproduces them almost exactly.

- LoRA (rank 16, 0.7% of parameters trained; 2 epochs on 4,000 training pairs, lr 3e-4,
  effective batch 16, ~25 min on a Colab T4) triples ROUGE-L over zero-shot Flan-T5,
  which answers in ~9 words and often just names the medicine.
- With noisy retrieved context, LoRA beats the extractive baseline (0.414 vs 0.395) because it
  learned to pick the relevant passage out of three instead of always copying the first one.
- Error analysis (app test): for "What is Coartem used for?" the right passage was retrieved but
  the reader copied text from a neighbouring passage; and "What is the exchange rate of the
  Rwandan franc?" was misclassified as health advice, but the retrieval-similarity threshold
  still returned "I couldn't find reliable information". US label text can mention US-only
  services (Poison Control 1-800-222-1222); answers are post-processed to point to 912 instead.

### Chat reader (Qwen2.5-1.5B-Instruct + LoRA)

The Flan-T5 reader copies the first sentences of a passage, so answers start mid-leaflet ("Use For
women to ...") and it cannot say that the passages do not answer the question. The chat reader
fine-tunes Qwen2.5-1.5B-Instruct (Qwen Team, 2024) with LoRA (r=16 on attention and MLP
projections, ~1% of parameters, fp16, 1 epoch, Colab T4) on targets built from the same grounded
QA pairs, no external LLM (`pharmqa/generation/chat_common.py`):

- **answer**: question + gold passage + 2 hard negatives → a direct opening sentence chosen by the
  question type ("Metformin can cause side effects.") + the cleaned gold passage;
- **overview**: "tell me everything about X" + 3–5 sections of X → a headed multi-section answer;
- **no answer** (~8%): question + 3 passages about other topics → "my sources don't cover this".

The loss is on the answer tokens only. `pharmqa/generation/evaluate_chat.py` reports ROUGE-L
(F1 and recall), BERTScore, *support* (share of answer content words found in the passages, a
groundedness proxy) and abstention on unrelated passages. The app uses the chat reader when its
adapter is present and falls back to Flan-T5 + LoRA otherwise (`FARUMASI_READER=flan` forces it).
Train and evaluate with `notebooks/train_chat_reader_colab.ipynb`.

Same 199 stratified test questions as the Flan-T5 table (3,000 answer + overview + no-answer
examples, 1 epoch on a Colab T4). "Retrieved" uses BM25 top 3 in this run, as in the Flan-T5 rows.

| Reader | Context | ROUGE-L | ROUGE-L recall | BERTScore-F1 | Support | Avg words | Abstains on unrelated passages |
|---|---|---|---|---|---|---|---|
| Flan-T5-base + LoRA | gold | 0.608 | | 0.900 | | 37 | cannot abstain |
| Qwen2.5-1.5B zero-shot | gold | 0.327 | 0.350 | 0.829 | 0.624 | 58 | 25% |
| **Qwen2.5-1.5B + LoRA** (deployed) | gold | **0.643** | **0.900** | **0.911** | **0.964** | 104 | **73%** |
| Flan-T5-base + LoRA | retrieved | 0.414 | | 0.841 | | 35 | cannot abstain |
| **Qwen2.5-1.5B + LoRA** | retrieved | **0.432** | 0.607 | **0.847** | 0.930 | 99 | 73% |

- LoRA doubles ROUGE-L over zero-shot Qwen (0.327 → 0.643). The zero-shot model paraphrases freely,
  and only 62% of its content words come from the passages (support 0.62, against 0.96 after
  fine-tuning), so it adds details that are not in the sources.
- The chat reader beats the Flan-T5 reader on both contexts while writing ~3× longer answers: it
  keeps 90% of the reference (ROUGE-L recall) and adds a direct opening sentence and more of the passage.
- It abstains on 73% of questions whose passages are about other topics (zero-shot: 25%), and
  never abstained wrongly when the right passage was present (false abstention 0%). In the
  remaining 27% it can answer from a loosely related passage (e.g. "Childbirth problems" answered
  with a family-history checklist), so the retrieval similarity threshold is kept as a second guard.

### Fixes from testing the live app

Testing the deployed app with realistic patient messages exposed failures the benchmark did not
measure. They were fixed in the answering pipeline (`pharmqa/query.py`, `pharmqa/pipeline.py`)
without retraining any model, so the tables above are unchanged.

| Patient message | Before | Cause | Fix |
|---|---|---|---|
| "hey", "thank you" | Out-of-scope refusal | Intent classes have no greeting class | Rule-based small-talk replies |
| "after sex pills for pregnancy prevention" | Generic "medicines in pregnancy" text | Lay wording; the stored levonorgestrel label was a daily combined pill | Lay/brand-name expansion (morning-after pill, panadol, brufen, flagyl, septrin...) and the OTC emergency-contraceptive label |
| "side effects of metformin" | Metoclopramide side effects | Reader copied the third passage (another drug); the stored metformin label was a sitagliptin + metformin combination | Re-rank passages about the medicine named in the question (+section, e.g. "side effects") and give the reader only those; single-ingredient metformin label |
| "Can I take panadol while pregnant?" | Tramadol pregnancy section | Brand name unknown to the retriever | Brand-name expansion |
| "Should Coartem be taken with food?" | Garbled leaflet text | Noisy two-column PDF passage | Brand → generic expansion reaches the clear FDA dosage section ("should be taken with food") |
| "examples of those pills", "what do they do?" | Out-of-scope refusal / no information | Every message was answered on its own, with no memory of the conversation | Short follow-ups with a pronoun ("those", "it", "they", "more") and no medicine of their own inherit the previous question's subject; the app shows "Understood as" |
| "can I get more info on them", "I need a full and detailed answer" | The same one-line answer every time | The reader always picks the single best passage | Detail requests get an overview of up to five leaflet sections (uses, how to take, who should not take it, side effects, examples); each further "more" adds sections not shown yet (warnings, interactions, pregnancy, storage), then says that is all the sources contain |
| "can I get some examples of those pills" | No information | No brand names in the corpus | "Examples" passages built from brand names on US FDA labels, with a note that Rwandan brands differ |
| "you keep saying same things", "you're stupid" | Treated as a follow-up / out-of-scope refusal | No handling of feedback | Polite reply explaining how to ask for one section or for full details |
| "which pills before sex to get the best experience" | Menopause hormone therapy text | Lay wording (and a typo) matched nothing | Lay-term rule → erectile dysfunction / sexual problems in men (NIH passages that advise seeing a doctor) |
| "are there any of 120hrs, I already passed 72hrs" | Warnings and storage of the morning-after pill | No ulipristal label in the corpus; the repeat check turned the specific question into an overview | Ulipristal (ella, up to 120 hours) label + lay terms ("120 hours", "5 days", "passed 72"); the overview fallback only fires for vague follow-ups |
| "examples that I can find in Rwanda" | The US brand list as if it applied to Rwanda | No Rwandan emergency-contraceptive leaflet | The examples passage states that the sources have no list of products registered in Rwanda |
| "you not answering what I asked you?" | "I couldn't find reliable information" | Complaint not recognised | Added to the feedback rule |
| "what do you know about kopavitamins" | General vitamin text, as if it described the product | Product names absent from the sources were silently ignored | `NameChecker`: a product name after "about / called / taking..." that appears nowhere in the corpus gets an honest "I don't have information about a product called ...", plus general information when a known word is inside it ("vitamins"); no false alarms on 600 test questions (`scripts/check_names.py`) |
| "what do you know about quarteme" | "I couldn't find reliable information" | Misspelt brand name | Closest known medicine name (fuzzy match): "the closest name in my sources is coartem", then the Coartem overview |
| "after sex pills" (just a name) | Dosage only | Treated as a narrow question | A bare name gets the overview |
| "what is that?" | "Levonorgestrel can cause side effects. Use for women to ..." | The chat reader sometimes picks the opening sentence of another section | "What is that/it" maps to the uses section, and an opening sentence announcing a different section than the one asked is replaced |

The original download picked, for each medicine, the openFDA label with the most patient
sections, which sometimes selected a combination product. `scripts/fetch_supplementary.py`
fetches the correct single-product labels (`data/external/supplementary_labels.jsonl`); the app
swaps them in at start-up, using embeddings precomputed with the trained retriever
(`artifacts/supplementary_embeddings.npy`; ZeroGPU Spaces must not run models at start-up). Label cross-references
("[see Warnings and Precautions (5.1)]") and US adverse-event reporting boilerplate are removed
before the reader sees a passage. `scripts/smoke_questions.py` reruns these messages end to end.

## Reproduce

```bash
pip install -r requirements.txt
python -m pharmqa.data.download        # openFDA, MedQuAD, MedicationQA, CLINC150, HealthCareMagic
python -m pharmqa.data.prepare         # corpus + grouped QA splits
python -m pharmqa.data.intent_data     # intent classifier data
python -m pharmqa.intent.baseline      # TF-IDF baselines (CPU, ~1 min)
python -m pharmqa.retrieval.bm25       # BM25 baseline (CPU)
python -m pharmqa.safety_eval
# GPU recommended (Colab T4): see notebooks/train_on_colab.ipynb
python -m pharmqa.intent.transformer --train_file train_consumer
python -m pharmqa.retrieval.dense --mode all
python -m pharmqa.generation.train_lora --epochs 2 --max_train 4000   # settings behind the reported results
python -m pharmqa.generation.evaluate --system lora --context retrieved
python -m pharmqa.generation.train_chat_lora --epochs 1 --max_train 3000          # Qwen chat reader
python -m pharmqa.generation.evaluate_chat --system lora --context gold --n 200
python -m pharmqa.report_tables
python app.py                          # local web app
python scripts/deploy_space.py --space Emmanuel-NS/farumasi-pharmacist-qa   # needs HF_TOKEN; Space on free ZeroGPU hardware
```

## Limitations

- openFDA questions are templated (answers are real); US labels use US brand names and doses.
- Rwanda leaflet questions are also templated; some PDFs are two-column layouts whose extracted text interleaves columns, so a few passages are noisy, and half of the leaflets (scanned images) are missing.
- MedQuAD drug answers were removed by its authors for copyright, so medicine answers come mainly from FDA labels, which are written for clinicians.
- English only; Kinyarwanda and French questions are out of scope for this version.
- Intent augmentation labels are heuristic; the challenge set is small and was used to refine the safety rules, so its safety score is optimistic.
- ROUGE/BERTScore measure similarity to a reference, not clinical correctness.
- Both readers are trained on targets built from the passages, so answers keep label wording (written for clinicians) rather than plain-language summaries; general symptom questions ("headache, what can I take?") get a description of the condition more often than treatment advice.
- Only a few wrong or missing openFDA labels (metformin, levonorgestrel, ulipristal) were corrected; other medicines may have the same combination-product problem.
